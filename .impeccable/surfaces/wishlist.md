# Wishlist · Operate

Extend the established monthly library interface. A fifth navigation destination opens an opaque themed sheet, with the existing serif heading, a compact introduction and an add action. Use a vertical list of wishes rather than goal cards: title, optional observation/link, then explicit complete/edit/delete actions. At narrow widths actions wrap below the text. Two filters separate pending wishes from realized experiences. Creation/editing use an inline form with a required title, optional notes and optional HTTP(S) link. Preserve user casing, show recoverable errors without dropping the draft, and confirm deletion inline. Empty states contain no invented wishes. No new imagery, hover effects or focus rings. Preserve seasonal scenery, safe-area reservations and the existing fixed dream-card geometry.


## Reward integration

Wishlist entries additionally carry optional BRL amount and classification. Use the user's labels: barato ≤50, valor mediano ≤200, carinho ≤500, preciso me organizar >500. A filled amount derives the classification; without an amount the classification may be chosen or left blank. Keep all fields optional except title.

Reuse one reward editor in the goal's personalization section and the Big Dream settings: none, draw now, draw on completion, manual selection, create in wishlist. Include an optional upper value tier for draws, defaulting to unrestricted. Use inline empty/create/cancel states; never nest forms. Preserve existing custom reward text. A gift symbol on an existing group's settings control signals a configured reward without adding height to group headings. Keep completion draws stable through reopen and correction, separate from ordinary practice progress. The main menu order is dreams, collection, wishlist, analytics, calendar.
